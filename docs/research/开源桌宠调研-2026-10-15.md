# 开源桌宠调研与方案取舍

调研日期：2026-10-15  
适用项目：Token 喵，首版接入 Codex 的 Windows AI 用量桌宠  
关联方案：[开发方案 v0.3](../../开发方案.md)

## 1 结论与研究范围

继续采用 Tauri 2、Rust、React 和 SQLite。最值得参考的是桌宠的交互恢复、语义动作映射、资源包、渲染生命周期和安静运行机制；这些能力可以改善现有产品，而不增加模型推理依赖。用量来源、精确记账、账户归属与能力声明继续由本项目的数据契约管理。

选取 7 个公开项目，覆盖传统桌宠、AI 伙伴、IDE 宠物和 AI 编程任务桌宠。热度以调研时 GitHub 页面展示的累计 Star 近似值为线索，不代表近期增长榜、实际用户数、稳定性或资源占用。GitHub 匿名 REST 查询返回限流，以下使用官方仓库页面和发行页面；未取得精确计数或完整提交时间，不编造活跃度排名。

本次只读核对 README、许可证、发行说明及有代表性的源码，没有安装或运行这些项目。因此，源码中的限帧、缓存回收等是机制证据，不是本项目或对方的 Windows 性能实测结果。默认分支可能领先发行版，后续若复用代码，需要固定具体提交并重新核对许可证。

## 3 可迁移的设计

### 3.1 显示动作与业务事实分离

VS Code Pets 用有限状态与动作结束、继续、取消结果管理行为；AIRI 按渲染器分派状态；Open-LLM-VTuber 将角色表情映射放在模型配置层。这些机制支持“同一语义对应不同角色动作”的设计。[行为源码](https://github.com/tonybaloney/vscode-pets/blob/main/src/panel/states.ts)、[AIRI 舞台](https://github.com/moeru-ai/airi/blob/main/packages/stage-ui/src/components/scenes/Stage.vue)、[角色映射](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber/blob/main/src/open_llm_vtuber/live2d_model.py)

本项目决策：增加 pet_presenter，将已经去重的任务事实映射为显示意图，再交给 animation_controller。事实仍保存在账本；点击反馈、眨眼、休眠只是表现。正常结束、失败、中断和结果未知保留文字与图标差异，不能因为皮肤只有一个结束动作而全部表现为成功。多个任务并行时保留活动数量，单个完成事件只短暂提示。

### 3.2 动画资源使用开始、循环、结束分段

VPet 二开文档将动画拆为 PNG 序列和开始、循环、结束阶段；eSheep 以 XML 配置配合图集表达角色动画。可借鉴声明式资源，而不引入它们的运行时或完整 MOD 机制。[VPet 动画文档](https://github.com/LorisYounger/VPet/blob/main/Secondary%20Development%20Support%20Documentation.md)、[eSheep README](https://github.com/Adrianotiger/desktopPet#readme)

本项目决策：首版建立内置皮肤清单与语义动作映射，包含帧时长、锚点、命中区域、循环策略、缺帧回退、作者和许可。普通动作可以打断，拖动和关闭优先响应；不为了播放完整动画阻塞用户操作。动画不能执行脚本、调用模型或修改账本。

### 3.3 穿透与多屏定位必须可恢复

BongoCat 提供穿透与按修饰键临时交互的组合，位置约束考虑负坐标与相邻屏幕，并等待位置稳定后纠偏。[交互定义](https://github.com/ayangweb/BongoCat/blob/master/crates/bongocat-runtime/src/lib.rs)、[位置逻辑](https://github.com/ayangweb/BongoCat/blob/master/crates/bongocat-overlay/src/placement.rs)

本项目决策：首版保留托盘和注册快捷键找回宠物；增加拔掉副屏、远程桌面分辨率改变、拖动跨屏和 DPI 切换验收。拖动结束后再修正越界，不能拖动中反复吸回原屏。按住修饰键临时交互作为后续可选体验，需要另外验证，不为此启用全局按键内容采集。

### 3.4 降低动画负载并管理资源生命周期

BongoCat 帧调度会在隐藏时降频并跳过错过的帧；VPet 清理闲置动画缓存。AIRI 的官方开发复盘专门讨论重复加载、隐藏场景和纹理释放问题，说明仅降低帧率不足以管理长期运行成本。[帧调度](https://github.com/ayangweb/BongoCat/blob/master/crates/bongocat-runtime/src/pacing.rs)、[VPet 缓存](https://github.com/LorisYounger/VPet/blob/main/VPet-Simulator.Core/Graph/GraphCore.cs)、[AIRI 生命周期复盘](https://airi.moeru.ai/docs/en/blog/DevLog-2026.03.14/)

本项目决策：动画时钟与采集时钟分开。隐藏、锁屏或减少动画模式停止持续装饰动画，日志采集按原规则继续；恢复时直接展示当前状态，不追放积压动画。换肤和预览加载带代次，丢弃过期结果，释放旧纹理、订阅和定时器。通过反复切换、隐藏与恢复的真实内存和资源记录验收，不照搬对方的帧率或资源宣传。

### 3.5 AI 任务桌宠只借鉴交互，不继承未知的计量结论

clawd-on-desk 的发行记录持续处理工具批次、排队消息、子代理回调和不同客户端的适配问题；表现层源码将多会话优先级与动画回退分开，并避免同状态反复换动作。README 的多工具支持范围不能替代本项目的能力检测与实机证据。[v1.3.0 发行说明](https://github.com/rullerzhou-afk/clawd-on-desk/releases/tag/v1.3.0)、[状态仲裁](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/src/state-priority.js)、[动画回退](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/src/state-visual-resolver.js)

本项目决策：宠物保留“需要查看”的简洁提示，详情进入收件箱与对应会话。动画状态由 SourceAdapter 已验证事件驱动；暂停、沉默、进程存在、文件更新时间等弱信号不能自行升级为成功、失败或持续待审批。低可信来源保持“状态待确认”。

eSheep 的窗口代码区分屏幕工作区和边界，并处理失效显示器索引；显示时采用避免激活的属性，但部分不激活样式仅用于子窗口，源码还提醒反复置顶可能影响菜单焦点。因此本项目将“不抢输入焦点”作为实际验收，而不是依据某个窗口标志直接宣称通过。[FormPet.cs](https://github.com/Adrianotiger/desktopPet/blob/master/src/dotNet/FormPet.cs)

## 5 写入开发方案的取舍

| 优先级 | 进入方案的优化 | 验收重点 |
| --- | --- | --- |
| P0 首版细化 | 确定性的显示状态与动画控制器；五类基础动作与静态回退 | 多任务、失败、未知、重复及乱序事件不误导 |
| P0 首版细化 | 安静驻留、减少动画、穿透找回、工作区与 DPI 恢复 | 不抢输入焦点，不遮挡不可恢复，状态文字可读 |
| P0 首版细化 | 内置资源清单、限帧与暂停、资源加载销毁 | 内存与 CPU 维持原门槛，隐藏恢复不补播 |
| P1 后续体验 | 经校验的本地皮肤包导入、轻触反馈、受限移动与临时交互 | 资源限制、许可、卸载、失败回退和交互共存 |
| P2 独立研究 | Live2D 或 VRM 渲染器 | 单独证明资源收益、生命周期、SDK与素材许可，不并行强上两个渲染器 |
| 暂不纳入 | 完整养成、用 token 消耗喂养升级、任意代码 MOD、语音视觉聊天、读取全局输入驱动动画 | 避免偏离可靠用量记录与安静提醒目标 |

不按 token 花费、累计响应数或长时间工作奖励角色成长，也不因少用 AI 显示生病或负面惩罚。后续轻互动保持可关闭，不参与账户额度或任务完成判断。

## 6 验证边界

调研结论已转为开发方案中的设计和验收条目，不构成实现或运行效果的验收。后续涉及引入外部代码、动画素材、SDK、模型或改变发布许可时，固定版本后按实际文件核对；本轮不为候选项目安装依赖、执行启动脚本或调用付费模型。
