小柚 v6：Live2D／骨骼动画素材交接
检查日期：2026-10-17

一、交付内容与使用范围
本包同时提供 38 张角色关键帧与 28 张拆分 PNG。原生文件为 1024×1536、RGBA、8 bit/channel，保留生成器原始字节。
拆分图层已检查中性正面组合、睁闭眼与嘴型切换，以及双臂/尾巴 ±3°、后发 ±1° 的小幅摆动遮挡。
这是制作素材与定位数据，不是 PSD、Cubism .cmo3 工程、.moc3/.model3.json 运行模型或 Spine 工程。
关键帧是 12 个现有动作内部的局部变化，未包含完整动作间过渡、密集补间或行走步态。

二、先装配，再交给绑定工具
目标画布固定为 1024×1536。坐标原点在左上，x 向右、y 向下；left/right 均指画面左右。
layers/layer-manifest.json 是图层名称、父子关系、绘制顺序、旋转中心和定位的依据。
每张原始图的部件位置并不相同，不能把所有 PNG 直接按原点重叠。
placement.matrix = [a,b,c,d,tx,ty] 将原图像素映射到目标画布：
  x' = a*x + c*y + tx
  y' = b*x + d*y + ty
必须先应用此矩阵，再围绕目标画布中的 pivot 旋转。不要把 pivot 当成原图坐标，也不要重复累乘已装配的父图层定位矩阵。
按 zIndex 从小到大绘制。parent 是后续建立运动层级的提示，不表示源 PNG 已经完成骨骼绑定。
参考 preview.html 的“分层”模式及 layers/assembly-review.html。后者提供并排原角色参考和有限幅度摆动测试。

三、Cubism 制作文件
在图像编辑器里按上述位置装配为独立、唯一命名的图层，保存为 RGB、8 bit/channel 的 PSD；建议使用 sRGB。
每个可动部件在一个图层中，相关线稿与颜色合并到该部件；蒙版或图层效果按 Cubism 的输入要求预先处理。
本次未输出或验证 PSD 导入。透明 PNG 图层加 JSON 不能等同于可直接导入的 Cubism 模型文件。
导入后仍需建立网格、变形器、参数范围、裁剪、物理、动作和运行时导出文件，并在目标运行端检查。

四、表情与遮挡
每只眼有三种互斥配置：完整睁眼 eye-left/right；闭眼 eye-closed-left/right；拆分眼白 eye-white-left/right + iris-left/right。
同侧完整眼与拆分眼不能同时显示，否则会重影。虹膜移动时应受眼白区域裁剪；当前只验证居中位置。
嘴型 mouth-neutral 与 mouth-open 互斥；眉毛独立于眼睛。
尾巴根部位于后骨盆位置，由身体和裙子遮挡，运动时仍应保持后层关系。正面素材不展示背后开口的细部。
袖根、发根、腿根保留了遮挡重叠；已验证的摆动范围有限，不能外推到大幅抬臂或转身。

五、进一步细分和补画需求
当前手臂是袖子与手一体，腿是丝袜与鞋一体。大幅肘弯、独立手指、膝弯和鞋部转向需要网格变形或进一步拆分补画。
头部大角度转向需要补齐侧面和被遮挡区域；本包的正面拆分不能自动生成这些结构。
两种素材路线采用同一角色设计，但拆分图层是独立重绘，不能与整张序列帧逐像素混用或直接渐变切换。

六、现有桌宠接入
本次未改动 src 或当前运行素材。现有桌宠仍是静态姿势加整体 CSS 动效。
序列帧接入时按 animation-manifest.json 的固定画布、共享锚点、时长和顺序播放；不要逐帧按 alpha 外接框重新缩放，以免画面跳位。
绑定模型路线需另加相应渲染器和动作/状态映射；已有业务状态仍由程序决定，动画只负责表现。
